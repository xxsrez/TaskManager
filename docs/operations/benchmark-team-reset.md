# Временный reset Teams для benchmark

Статус: временная UAT-only процедура. Она существует только на время пяти
последовательных прогонов Issue Grinder и удаляется до закрытия TM-336.

## Граница

- Метод: `POST /api/admin/benchmark/teams/reset`.
- Маршрут отвечает только при `TASK_MANAGER_ATTACHMENT_SCOPE=uat`,
  `TASK_MANAGER_BENCHMARK_TEAM_RESET_ENABLED=true` и точном
  `Authorization: Bearer <TASK_MANAGER_BENCHMARK_TEAM_RESET_TOKEN>`.
- При любой ошибке допуска или отсутствующей конфигурации ответ — `404`, до D1
  запрос не доходит.
- Операция выполняет только `DELETE` из `team_grants`, затем
  `team_memberships`, затем `teams`; schema, migration и остальные таблицы не
  меняются.
- Ответ содержит только количество удалённых и оставшихся записей. Повторный
  вызов на пустом состоянии успешен и возвращает нули.
- Токен не хранится в Git, Task Manager, benchmark-артефактах, логах или теле
  ответа.

Маршрут не является продуктовым API. Его нельзя публиковать в production,
передавать дочерним прогонам или использовать для произвольной очистки D1.

## Контрольный вызов

Центральный контроллер после каждого прогона:

1. Сохраняет все артефакты прогона и post-run снимок трёх Team tables.
2. Возвращает UAT к точной временной baseline-версии с этим маршрутом.
3. Вызывает маршрут с секретом из hosted UAT configuration.
4. Проверяет `200`, удалённые количества и нулевой `remaining` для всех трёх
   таблиц.
5. Повторно считывает D1 и сверяет protected-table fingerprints с baseline.
6. Только после успешной проверки начинает следующий режим.

Пустой вызов до первого прогона подтверждает доступность и идемпотентность.
Первый непустой post-run reset служит live-проверкой удаления реальных
benchmark-записей.

## Обязательное удаление

После пятого прогона и слепой оценки, но до закрытия TM-336:

1. Удалить маршрут, его модуль, тест и этот runbook.
2. Удалить обе переменные из runtime types, Worker environment и
   `.env.example`.
3. Удалить hosted UAT flag и secret.
4. Влить удаление в `main`, опубликовать точный SHA в UAT и проверить, что
   маршрут отвечает `404` независимо от прежнего bearer-токена.
5. Подтвердить нули во всех трёх Team tables и неизменность protected tables.

Сохранённые benchmark-артефакты и итоговый сравнительный отчёт остаются; сам
операционный канал и его секрет — нет.
