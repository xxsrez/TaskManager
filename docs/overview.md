# Обзор продукта

Статус: `Proposed`

Последнее обновление: 2026-08-13

## Замысел

Task Manager — быстрый и визуально спокойный трекер для работы, которую удобно
разложить на задачи, проекты и релизы. Он заимствует у Linear строгую модель
задачи и единые представления данных, но сознательно не воспроизводит
организационную, аналитическую и интеграционную платформу Linear.

Главная единица работы — `Task`. `Project` объединяет задачи вокруг конечного
результата. `Release` отвечает на вопрос «что и когда поставляем» внутри
проекта. `SavedView` сохраняет способ найти и показать текущие задачи. Kanban —
это один из layout представления, а не отдельный набор данных.

## Для кого

Первая версия рассчитана на одного пользователя или небольшую группу, которым
нужны:

- единый backlog и прозрачный workflow;
- проекты с конечной целью и сроком;
- планируемые и завершённые релизы;
- быстрые срезы по метаданным;
- list и Kanban без сложной настройки процессов.

Точная модель аккаунтов и совместной работы пока не выбрана. Наличие
`assignee` и `lead` в домене не означает, что многопользовательская
аутентификация уже включена в первый срез реализации.

## Продуктовые принципы

1. **Одна модель, разные проекции.** Список, Kanban и сохранённый view читают
   одни и те же задачи.
2. **Минимум обязательных полей.** Для новой задачи достаточно заголовка;
   система назначает начальный статус и идентификатор.
3. **Метаданные должны работать.** Поле оправдано, если по нему можно искать,
   фильтровать, группировать, сортировать или управлять workflow.
4. **Релиз не равен Done.** Завершение работы и поставка результата — разные
   факты.
5. **Настройка без распада семантики.** Названия статусов можно менять, но их
   системные категории остаются стабильными.
6. **Архив вместо потери истории.** Обычное удаление из активной работы должно
   быть обратимым; необратимое удаление — отдельное подтверждаемое действие.

## Границы MVP

В MVP входят:

- создание, редактирование, архивирование и восстановление задач;
- настраиваемый workflow и системные категории статусов;
- task metadata: приоритет, исполнитель, проект, релиз, labels, estimate,
  due date, parent/subtasks и связи между задачами;
- проекты с описанием, статусом, lead, датами и прогрессом;
- релизы проекта с датой, статусом, составом и release notes;
- list и Kanban над одинаковым набором задач;
- фильтры, группировка, сортировка, видимые поля и сохранённые views;
- базовый поиск по идентификатору, заголовку и описанию.

Не входят в MVP:

- teams, initiatives, cycles/sprints и roadmap/timeline;
- project milestones как отдельная от release сущность;
- inbox/triage, комментарии, документы и вложения;
- уведомления, подписки и activity feed;
- Git/CI/CD, Slack, email и другие интеграции;
- analytics, forecasting, AI-фильтры и генерация release notes;
- мобильные приложения, offline-first и real-time collaboration.

## Основной пользовательский цикл

1. Пользователь создаёт проект и при необходимости его первый релиз.
2. Создаёт задачи, оставляя необязательные поля пустыми или заполняя metadata.
3. Открывает готовый либо сохранённый view.
4. Работает в list или Kanban; фильтры определяют состав, display options —
   способ показа.
5. Перемещает задачи по workflow и видит прогресс проекта и релиза.
6. Завершает релиз отдельно от перевода отдельных задач в Done.

## Критерий успеха первого продукта

Пользователь может вести реальный небольшой проект только в Task Manager:
добавить backlog, сформировать релиз, ежедневно работать с Kanban, открыть
несколько сохранённых срезов и по завершении точно увидеть состав выпущенного
релиза. Это продуктовая цель, а не уже подтверждённый результат.

## Открытые продуктовые решения

- персональный продукт или совместная рабочая область;
- нужны ли private/shared views уже в первом публичном срезе;
- должен ли проект разрешать несколько одновременно активных релизов;
- какие операции необратимого удаления допустимы;
- требуется ли импорт из Linear/CSV в первой версии после MVP.
